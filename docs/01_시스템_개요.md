# 01. 시스템 개요

## 1. 이 시스템은 무엇인가

기관·기업의 **내부 규정(사규·법령)을 등록·개정·공포·열람**하고, 필요하면 **소송 사건을
관리**하는 웹 시스템입니다. 전자정부 표준프레임워크 4.3.0 위에 두 개의 도메인 모듈을
얹은 구조입니다.

| 도메인 | URL 네임스페이스 | 자바 패키지 | 한 줄 설명 |
|---|---|---|---|
| **규정관리** | `/rlms/**` | `narainet.rlms.*` | 규정을 조문 단위로 관리하고 개정 이력을 쌓는다 |
| **송무** | `/law/**` | `narainet.law.*` | 소송 사건·기일·비용·변호사를 관리한다 |
| **공통 기반** | 그 외 | `egovframework.com.*` | 전자정부 표준 공통컴포넌트(사용자·권한·메뉴·게시판·파일) |

세 제품은 이 조합만 다릅니다.

- **RLMS** = 규정관리 + 송무 + 공통 (통합본)
- **RegNex** = 규정관리 + 공통
- **LexPortal** = 송무 + 공통

## 2. 규정관리 도메인

### 2.1 핵심 개념 — "규정"이 아니라 "회차"

이 시스템의 기본 단위는 규정 자체가 아니라 **회차(공포 시점의 한 판본)** 입니다.

```
규정 "임직원 행동강령"   ← 논리 식별자 ILAW_ID 로 묶인 그룹
 ├─ 회차 1  제정      2020-01-01 시행   (IPROM_NO=101)
 ├─ 회차 2  일부개정  2023-05-01 시행   (IPROM_NO=340)
 └─ 회차 3  전부개정  2026-03-01 시행   (IPROM_NO=982)  ← 현행
```

- 회차 1건 = `TB_PROM` 1행. 같은 규정의 회차들은 `ILAW_ID` 가 같습니다.
- **현행 판정**은 시행일(`SSTART_DT`) ≤ 오늘 < 폐지일(`SNULL_DT`) 로 합니다.
- 조문·별표·관련자료는 **모두 회차에 매답니다**. 그래서 "2023년 기준 제5조" 를
  그대로 재현할 수 있습니다.

### 2.3 조문 본문 모델 (중요)

조문 본문은 **두 가지 형식**을 병행 지원합니다. `TB_PROM.SPROV_FG` 가 어느 쪽인지
가리킵니다.

| 형식 | 저장 테이블 | 특징 |
|---|---|---|
| **VERSION**(구조형) | `TB_PROV_VRSN` | 조/항/호를 **행 단위로 분해**. 회차 간 비교·조문 링크·부분 개정이 가능 |
| **HTML**(자유형) | `TB_PROV_HTML` | 조 단위로 HTML 본문 1행. 표가 많은 규정에 유리 |

구조형은 저장 시 평문 텍스트를 파서(`ProvTextParser`)가 조/항/호로 분해해서
`TB_PROV_VRSN` 에 적재합니다. **본문 입력은 평문 textarea 가 정본**이며 에디터가
아닙니다.

### 2.4 개정처리 — 누적 모델

개정 회차는 **바뀐 조문만** 저장합니다(누적 모델).

- 신규 회차를 만들면 직전 회차의 조문을 복사해 온 뒤,
- 변경/신규 조문과 삭제 표식(tombstone, `SDISP_YN='N'`)만 새 회차가 소유합니다.
- 따라서 어떤 회차를 조회하든 "그 시점 전문" 을 온전히 재구성할 수 있습니다.

## 3. 송무 도메인

### 3.1 핵심 개념 — "심급 1건 = 1행"

`LAW_SUIT` 한 행이 **하나의 심급**입니다. 1심·2심·3심은 각각 별도 행이고,
`FIRST_SUIT_ID` 로 같은 사건군으로 묶입니다.

```
사건군 (FIRST_SUIT_ID = 1001)
 ├─ SUIT_ID=1001  1심  창원지방법원   2024가합1234
 ├─ SUIT_ID=1055  2심  부산고등법원   2025나5678
 └─ SUIT_ID=1120  3심  대법원         2026다9012
```

### 3.3 주민등록번호 취급

당사자 주민등록번호(`LAW_SUIT_PARTY.JUMIN_ENC`)는 **ARIA 로 암호화해서** 저장하고
화면에서는 마스킹만 보여줍니다. 키는 `Globals.law.cryptoKey` 이며 **고객사 전용
값으로 반드시 교체**해야 합니다(`04_개발규약_아키텍처.md` §9).

## 5. 권한 모델 (3-tier + 옵션 2종)

| ROLE | 대상 | 범위 |
|---|---|---|
| `ROLE_ADMIN` | 시스템관리자 | 전체 |
| `ROLE_EDITOR` | 편집자 | 규정·분류·부서·개정구분 편집 |
| `ROLE_APPROVER` | 승인자 | EDITOR + 승인/반려 |
| `ROLE_USER` | 조회자 | 사용자 화면 — 조회·메모·즐겨찾기 |
| `ROLE_LAW_MGR` | 송무담당자 | 송무 모듈 전용 (RLMS·LexPortal) |

> **URL 접근제어의 원천은 코드가 아니라 DB 입니다.** 화면을 새로 만들면
> 프로그램(`COMTNPROGRMLIST`) → 메뉴(`COMTNMENUINFO`) → 메뉴별 권한
> (`COMTNMENUCREATDTLS`) 3곳에 등록해야 접근이 열립니다. 자세한 내용은
> `04_개발규약_아키텍처.md` §6.

## 6. 공개 열람 모드

`Globals.rlms.publicFront` 로 첫 화면 정책을 정합니다.

| 값 | 동작 |
|---|---|
| `Y` (기본) | 비로그인도 사용자 홈·규정 열람 가능. 분류별 열람제한은 익명에도 그대로 적용 |
| `N` | 로그인 화면이 첫 화면 (비공개 운영) |

- 개인화·쓰기 기능(즐겨찾기·메모·필수열람·만족도·Q&A·게시판·내계정)은 공개 모드에서도
  **로그인이 필요**합니다.
- 이 값은 **기동 시 1회 판정**되므로 변경하면 **서버 재기동**이 필요합니다.
