# 02. 설치 가이드 (Eclipse + Tomcat)

> 순서대로 따라 하면 브라우저에서 로그인까지 됩니다.
> **DB 가 먼저 준비되어 있어야 합니다** → `03_데이터베이스_가이드.md` 를 먼저 수행하세요.

---

## 1. 사전 준비물

| # | 항목 | 버전 | 확인 방법 / 비고 |
|---|---|---|---|
| 1 | **JDK 1.8** | 1.8 (8u..) | `java -version`. 컴파일 대상이 1.8 이라 **필수**. 9+ 로 빌드하면 안 됩니다 |
| 2 | **Maven** | 3.9.x | `mvn -v`. eGovFrame 개발자용 패키지에 동봉된 것을 그대로 써도 됩니다 |
| 3 | **Apache Tomcat** | **9.0.x** (정본) | 10.0 · 11.0 도 됩니다 — `javax.*` → `jakarta.*` 라 **배포 시 `migrate.bat` 1회** 필요(소스 무수정). 절차는 **§5.3** |
| 4 | **Eclipse** | eGovFrameDev 4.3.1 권장 | WTP(Server) + m2e 플러그인 필요 |
| 5 | **DBMS** | Oracle 11g+ / MariaDB 10.x / PostgreSQL 13+ | 셋 중 하나 |
| 6 | (선택) **JDK 21** | 21.x | `tools/` 의 JDBC 도구가 `ojdbc11` 을 쓰므로 필요. 앱 빌드와는 무관 |

> **JDK 를 두 개 쓰는 이유**: 애플리케이션은 1.8 로 빌드/구동하고, 부속 점검 도구
> (`tools/dbq` 등)만 최신 Oracle 드라이버 때문에 21 을 씁니다. 도구를 안 쓰면 21 은
> 없어도 됩니다.

## 2. 프로젝트 배치

이 패키지의 제품 폴더(`RLMS`, `RegNex`, `LexPortal`)를 **Eclipse 워크스페이스 폴더로
복사**합니다.

```
C:\eGovFrameDev-4.3.1-64bit\workspace\
├─ RLMS\
├─ RegNex\
└─ LexPortal\
```

> 워크스페이스 경로가 위와 다르면 `tools/` 의 스크립트 기본값만 달라집니다.

> 셋 중 실제로 쓸 제품 하나만 복사해도 됩니다.

## 3. Eclipse 임포트

1. **File → Import… → Maven → Existing Maven Projects**
2. Root Directory = 워크스페이스 폴더 선택
3. 목록에 `RLMS`, `RegNex`, `LexPortal` 의 `pom.xml` 이 보이면 **Finish**

임포트 직후 확인할 것:

| 확인 항목 | 정상 상태 | 틀렸을 때 |
|---|---|---|
| 프로젝트 JRE | **JavaSE-1.8** | Properties → Java Build Path → Libraries → JRE System Library 편집 |
| Project Facets | Dynamic Web Module 3.x + Java 1.8 | Properties → Project Facets |
| Targeted Runtime | Apache Tomcat v9.0 | Properties → Targeted Runtimes 체크 |
| 텍스트 인코딩 | **UTF-8** | Properties → Resource → Text file encoding |

> `.project` / `.classpath` / `.settings/` 를 함께 드렸으므로 대부분 자동으로 맞습니다.
> Tomcat 런타임 이름이 다르면 Targeted Runtimes 만 다시 체크해 주세요.

## 4. 빌드

### 4.1 최초 1회 — 온라인 빌드

의존성을 내려받아야 하므로 **인터넷이 되는 상태**에서 한 번 돌립니다.

```bash
mvn -f RLMS/pom.xml compile
```

- 저장소는 `pom.xml` 에 Maven Central + 전자정부 표준프레임워크 저장소
  (`https://maven.egovframe.go.kr/maven/`) 가 등록되어 있습니다.
- 일부 상용 JDBC 드라이버(ojdbc6, tibero5 등)는 **프로젝트 안에** 들어 있습니다
  (`src/main/webapp/WEB-INF/lib/project/`). 별도 설치가 필요 없습니다.

### 4.2 이후 — 오프라인 빌드

```bash
mvn -o -f RLMS/pom.xml compile
```

- **`clean` 을 붙이지 마세요.** `target/` 을 지우면 WTP 배포본까지 날아가
  Tomcat 을 다시 배포해야 합니다. 증분 컴파일로 충분합니다.
- `package`(WAR 생성)는 플러그인을 추가로 받아야 해서 **오프라인에서는 실패**합니다.
  WAR 가 필요하면 온라인에서 `mvn -f RLMS/pom.xml package`.

## 5. Tomcat 서버 등록과 기동

### 5.1 Eclipse WTP 로 띄우기 (개발 중 권장)

1. **Servers 뷰 → New → Server → Apache Tomcat v9.0**
2. 생성된 서버를 더블클릭 → **Server Options** 에서
   - ☑ *Serve modules without publishing* 은 **끄고**,
   - **Publishing** 은 *Automatically publish when resources change* 로 둡니다.
3. **Modules 탭 → Add Web Module** 로 제품을 추가
4. 서버 시작

**포트를 UTF-8 로 열어야 합니다.** 서버 설정의 `server.xml` 에서 HTTP 커넥터에
`URIEncoding="UTF-8"` 이 있는지 확인하세요. 없으면 한글 파라미터가 깨집니다.

```xml
<Connector URIEncoding="UTF-8" port="7070" protocol="HTTP/1.1"
           connectionTimeout="20000" redirectPort="8443" />
```

### 5.2 세 제품을 동시에 띄울 때

포트와 shutdown 포트가 겹치면 안 됩니다. 참고용 `server.xml` 두 개를 동봉했습니다
(`tools/multidb/tomcat/`).

| 제품 | HTTP 포트 | shutdown 포트 | 참고 파일 |
|---|---:|---:|---|
| RLMS | 7070 | 8005 | (기본값) |
| LexPortal | 7071 | 8008 | `server-lexportal-7071.xml` |
| RegNex | 7072 | 8007 | `server-regnex-7072.xml` |

> 동봉한 `server-*.xml` 의 `<Context docBase="…">` 경로는 개발사 기준으로
> 적혀 있습니다. **본인 워크스페이스 경로로 고쳐서** 쓰세요.

### 5.3 Tomcat 10 / 11 에서의 구동 — 실측 결과

**이 패키지의 기준은 Tomcat 9 입니다.** 그대로 배포하면 됩니다.
Tomcat 10 이상을 요구받는 경우만 이 절을 보십시오.

| WAS | Servlet | 결과 | 필요한 작업 |
|---|---|---|---|
| **Tomcat 9.0.x** | 4.0 | ✅ **정본** | 없음 |
| **Tomcat 10.0.x** | 5.0 | ✅ 동작 (스모크 32/32) | 배포 시 `migrate.bat` 1회 — **소스 무수정** |
| Tomcat 10.1.x | 6.0 | ⚪ 미실측 | 11 이 되므로 문제없을 것으로 보나 확인하지 않았습니다 |
| **Tomcat 11.0.x** | 6.1 | ✅ **동작** (스모크 32/32 · 레이아웃 75/75) | 배포 시 `migrate.bat` 1회 — **소스 무수정** |

Tomcat 10 부터 `javax.*` → `jakarta.*` 로 네임스페이스가 바뀝니다. 이 자체는 Tomcat 이
제공하는 변환 도구로 해결됩니다(실측 **32~40초, 파일 손실 0**).

> 2026-08-06 까지는 Tomcat 10.1 이상에서 동작하지 않았습니다. 레이아웃 엔진(SiteMesh)의
> "버퍼링 후 dispatch" 방식이 Servlet 6.0 의 응답 커밋 동작과 충돌했기 때문입니다.
> **2026-08-07 에 SiteMesh 를 제거하고 레이아웃을 JSP 태그파일로 옮겨 해소했습니다.**
> 경위는 [08_현재_한계와_향후과제.md](08_현재_한계와_향후과제.md) §1 에 있습니다.

#### Tomcat 10.0 / 11 로 배포하는 절차

```bash
set JAVA_HOME=<JDK 17>
set CATALINA_HOME=<Tomcat 경로>
%CATALINA_HOME%\bin\migrate.bat <빌드된 webapp 경로> <변환 결과 경로>
```

- ⚠️ `CATALINA_HOME` 을 설정하지 않으면 `migrate.bat` 이 **아무 일도 하지 않고 종료**합니다
  (오류 메시지만 출력하고 종료 코드는 0). 변환 후 파일 수를 원본과 대조해 확인하십시오.
- 변환 결과를 `webapps\ROOT` 로 배포합니다(Context path 는 `""` 여야 합니다).
- `conf\server.xml` 커넥터에 `URIEncoding="UTF-8"` 을 넣습니다.
- `Host` 의 `legacyAppBase`(기본 `webapps-javaee`)에 WAR 를 두면 기동 시 자동 변환됩니다.
- Tomcat 11 은 **JDK 17 이상**이 필요합니다(소스 문법은 여전히 Java 8 고정 — `docs/08` §2).

배포 후 `tools/smoke.ps1` 과 `tools/layoutcheck.ps1` 로 확인하시길 권합니다.

> Tomcat 10.0.x 는 지원 종료 계열입니다(마지막 릴리스 10.0.27). 보안 관점에서는
> 아직 유지보수 중인 Tomcat 9 대비 이득이 없으니, 요건이 형식적일 때만 쓰십시오.

### 5.4 로그 설정 (선택)

`<제품>/tools/tomcat/logging.properties` 를 쓰면 애플리케이션 로그가 별도 파일로
떨어집니다. Tomcat 기동 VM 인자에 추가하세요.

```
-Djava.util.logging.config.file="<경로>\tools\tomcat\logging.properties"
```

## 6. 애플리케이션 설정

`<제품>/src/main/resources/egovframework/egovProps/globals.properties`

### 6.1 반드시 채워야 하는 것

```properties
# 사용할 DBMS 선택 — oracle | maria | postgres | tibero
Globals.DbType = oracle

# 선택한 DBMS 의 3개 항목 (★모두 암호문. 만드는 법은 03 문서 §4)
Globals.oracle.Url      = __ENCRYPTED_VALUE_REQUIRED__
Globals.oracle.UserName = __ENCRYPTED_VALUE_REQUIRED__
Globals.oracle.Password = __ENCRYPTED_VALUE_REQUIRED__

# 파일 업로드 루트 (반드시 절대경로, 끝에 / 포함)
Globals.fileStorePath = D:/upload/
```

> ⛔ **평문을 넣으면 예외가 나지 않고 "깨진 문자열"로 접속을 시도합니다.**
> 원인 찾기가 매우 어려우니, 세 항목 모두 암호문인지 꼭 확인하세요.

### 6.2 자주 건드리는 나머지

| 키 | 뜻 | 기본값 |
|---|---|---|
| `Globals.MainPage` | 로그인 후 첫 화면 | RLMS/RegNex `/rlms/index.do`, LexPortal `/index.do` |
| `Globals.rlms.publicFront` | 공개 열람 모드 (`Y`/`N`) | `Y` |
| `Globals.fileUpload.maxSize` | 업로드 최대 크기 | 52428800 (50MB) |
| `Globals.ExpirePwdDay` | 비밀번호 유효기간(일) | 180 |
| `Globals.DormantDay` | 휴면계정 기준일 | 365 |
| `Globals.rlms.PdfFontPath` | PDF 내보내기 한글 폰트 | `C:/Windows/Fonts/malgun.ttf` |

> **프로퍼티는 기동 시 1회만 읽습니다.** 값을 바꿨으면 반드시 **Tomcat 재기동**.

## 7. 첫 기동 검증

브라우저에서 `http://localhost:7070/` 접속.

### 7.1 시드 계정

| 계정 | 비밀번호 | 권한 | 첫 화면 |
|---|---|---|---|
| `sysmen` | `asdqwe123!` | ROLE_ADMIN | 관리자 대시보드 |
| `approver` | `rlms1234!` | ROLE_APPROVER | 승인 대기 목록 |
| `lawmgr` | `rlms1234!` | ROLE_LAW_MGR | 송무 홈 (RLMS·LexPortal) |
| `user` | `rlms1234!` | ROLE_USER | 사용자 홈 |

> ⚠️ **운영 전환 전에 반드시 전부 변경**하세요. 변경 방법은 `03` 문서 §6.

### 7.2 확인 동선 (규정관리 — RLMS/RegNex)

1. `sysmen` 로그인 → 관리자 대시보드가 그려지는가
2. 분류관리 → 구분 `법령`·`사규` 2건이 보이는가
3. 분류 1건 생성 → 규정 회차 등록 → 조문 저장
4. `approver` 로 승인 → 사용자 화면에서 열람
5. 통합검색에 방금 등록한 규정이 나오는가

### 7.3 확인 동선 (송무 — RLMS/LexPortal)

1. `lawmgr` 로그인 → 송무 홈
2. 소송관리 → 사건 등록(법원 목록이 22건 이상 뜨는지 = 기준데이터 확인)
3. 당사자 추가 → 주민등록번호 입력 후 저장 → 재조회 시 **마스킹**되어 보이는가
4. 소송비용 계산기 → 요율표가 로드되는가

### 7.4 자동 점검

```bash
powershell -ExecutionPolicy Bypass -File tools\smoke.ps1 -BaseUrl http://localhost:7070
```

주요 화면을 순회하며 HTTP 상태와 오류 화면 여부를 확인합니다
(`06_도구_사용설명서.md` §2).

## 8. 자주 겪는 문제

| 증상 | 원인 | 조치 |
|---|---|---|
| 기동 중 DataSource 예외 | 접속정보 3항목 중 하나가 평문/오타 | globals.properties 재확인 → **재기동** |
| 기동은 되는데 로그인 실패 | 시드가 안 들어감 | `22_seed_auth.sql`·`23_seed_org_accounts.sql` 실행 확인 |
| 한글 파라미터 깨짐 | 커넥터 `URIEncoding` 누락 | server.xml 에 `URIEncoding="UTF-8"` 추가 |
| 화면은 뜨는데 403 | 메뉴/프로그램/메뉴별권한 미등록 | `04` 문서 §6 — 신규 URL 은 DB 등록 필수 |
| 저장 시 "시스템 에러" | 채번(`COMTECOPSEQ`) 행 누락 | `26_seed_idgn.sql` 실행 확인 |
| JSP 수정이 반영 안 됨 | WTP 퍼블리시 지연 | 서버 우클릭 → Clean… 또는 `target/<제품>-1.0.0/` 에 직접 복사 |
| 클래스 수정이 반영 안 됨 | 핫스왑 한계 | 여러 번 반복되면 **선제적으로 재기동**(6~8회 리로드마다) |
| `mvn -o` 실패 | 로컬 저장소에 없음 | 한 번은 온라인으로 빌드 |

## 9. 배포(운영 반영)

```bash
mvn -f RLMS/pom.xml clean package     # 온라인 필요
# → target/RLMS-1.0.0.war
```

운영 서버에서는 아래를 서버 환경에 맞게 다시 확인합니다.

- `globals.properties` 의 DB 접속정보·업로드 경로 (운영 값으로)
- `Globals.OsType` (`UNIX` / `WINDOWS`)
- 업로드 디렉터리 쓰기 권한
- Tomcat 커넥터 `URIEncoding="UTF-8"`, JVM `-Dfile.encoding=UTF-8`
