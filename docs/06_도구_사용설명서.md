# 06. 도구 사용설명서

`RESULT/tools/` 에 들어 있는 검증·운영 도구 모음입니다.
**전부 선택 사항**이며, 없어도 시스템은 동작합니다. 다만 화면을 추가하거나 스키마를
고친 뒤에는 이 도구들이 회귀를 빨리 잡아 줍니다.

```
tools/
├─ smoke.ps1              앱 스모크 테스트 (제일 자주 씀)
├─ layoutcheck.ps1        화면 레이아웃 셸 검증 (래핑 누락·이중 래핑)
├─ authcheck.ps1          URL 인가 검증
├─ namecheck.ps1          메뉴명 ↔ 화면 제목 정합
├─ encpw/                 비밀번호 해시 생성
├─ dbq/                   Oracle 스크립트 러너
├─ dbdoc/                 테이블 명세서·ERD 재생성
├─ multidb/               Oracle → MariaDB/PostgreSQL 변환·적재·린트
├─ testdata/              문서 가져오기 테스트용 샘플 파일
└─ tomcat/                Tomcat 로깅 설정
```

## 0. 공통 사전 조건

| 항목 | 값 | 설정 방법 |
|---|---|---|
| 워크스페이스 경로 | 기본 `C:/eGovFrameDev-4.3.1-64bit/workspace` | `set RLMS_WS=<경로>` |
| JDK(도구용) | 기본 `C:\java\jdk-21.0.10` | `set RLMS_JDK=<경로>` |
| DB 접속 URL | 없음 | `set RLMS_DB_URL=jdbc:oracle:thin:@<host>:1521:<sid>` |
| DB 계정/비번 | 없음 | `set RLMS_DB_USER=…` / `set RLMS_DB_PASS=…` |

> ⚠️ PowerShell 스크립트(`*.ps1`)는 **UTF-8(BOM) 로 저장되어 있어야** 합니다.
> PowerShell 5.1 이 한글 리터럴을 그렇게 읽습니다. 편집할 때 인코딩을 바꾸지 마세요.

실행 예:

```bash
powershell -ExecutionPolicy Bypass -File tools\smoke.ps1
```

## 1. smoke.ps1 — 앱 스모크 테스트

로그인한 뒤 주요 화면·팝업·JSON 엔드포인트를 순회하며 회귀를 잡습니다.

```bash
powershell -ExecutionPolicy Bypass -File tools\smoke.ps1
powershell -ExecutionPolicy Bypass -File tools\smoke.ps1 -BaseUrl http://localhost:7070 -User sysmen -Pass '...'
```

| 파라미터 | 기본값 |
|---|---|
| `-BaseUrl` | `http://localhost:7070` |
| `-User` | `sysmen` |
| `-Pass` | `asdqwe123!` |

**왜 필요한가** — 이 시스템은 전역 예외 처리기가 예외를 잡아 "시스템 에러" 화면을
**HTTP 200 으로** 돌려줍니다. 상태 코드만 보면 다 정상으로 보입니다.
스모크는 본문의 한글 오류 문구까지 검사합니다.

> ⚠️ **중복 로그인 방지 정책** 때문에, 스모크가 로그인하면 같은 계정으로 열어 둔
> 브라우저 세션이 끊깁니다. 화면을 보면서 돌릴 때는 다른 계정을 쓰세요.

제품별 스모크(포트가 다름):

```bash
powershell -ExecutionPolicy Bypass -File tools\multidb\smoke_regnex.ps1      # 7072
powershell -ExecutionPolicy Bypass -File tools\multidb\smoke_lexportal.ps1   # 7071
```

## 1.5 layoutcheck.ps1 — 화면 레이아웃 검증

메뉴에 걸린 **전 화면을 훑어 "셸이 정확히 한 겹인지"** 확인합니다.

```bash
powershell -ExecutionPolicy Bypass -File tools\layoutcheck.ps1 -DbPass '<스키마 비밀번호>'
powershell -ExecutionPolicy Bypass -File tools\layoutcheck.ps1 -Urls '/rlms/index.do','/cop/bbs/...'
```

| 파라미터 | 설명 |
|---|---|
| `-DbPass` | 메뉴 표에서 점검 대상 URL 을 자동 수집합니다 *(Oracle 전용)* |
| `-Urls` | DB 없이 점검할 URL 을 직접 지정합니다 |
| `-SelfContained` | 셸이 **없는 것이 정상**인 화면(기본 `/index.do`) |
| `-BaseUrl` / `-User` / `-Pass` | smoke.ps1 과 동일 |

화면당 이것들을 봅니다 — `<html>`/`<body>`/`<!DOCTYPE>` 이 각각 정확히 1개,
`</html>` 로 끝남, 셸 마커가 정확히 1종, `<title>` 이 비어있지 않음.

**왜 필요한가** — 레이아웃이 필터가 아니라 **화면 JSP 자신**이 두르는 구조라
(`docs/04` §8.1), 새 화면을 만들 때 두 가지 실수가 가능합니다.

1. **래핑 누락** — `<lay:layout>` 을 안 써서 헤더·GNB 없는 맨몸 HTML 이 뜸
2. **이중 래핑** — 감싸면 안 되는 화면(자체 완결 레이아웃, `c:import` 대상)을 감싸
   문서 한가운데에 `<html><head>` 가 박힘

둘 다 HTTP 200 이라 스모크로는 안 잡힙니다. **화면을 추가·수정하면 이걸 돌리십시오.**

## 2. authcheck.ps1 — URL 인가 검증 *(Oracle 전용)*

**403 사고를 가장 확실하게 잡는 도구입니다.**

```bash
powershell -ExecutionPolicy Bypass -File tools\authcheck.ps1 -DbPass '<DB 비밀번호>'
```

| 파라미터 | 기본값 |
|---|---|
| `-DbPass` | (필수) |
| `-BaseUrl` | `http://localhost:7070` |
| `-DbUser` | `RLMS` |

두 가지를 봅니다.

1. **인가 매트릭스** — 계정 × 전 메뉴. 규칙이 말하는 "기대"와 실제 HTTP 응답을 대조합니다.
   어긋나면 **권한 누수**이거나 **오차단**입니다.
2. **메뉴 노출 정합** — 화면에 링크로 그려져 있는데 누르면 막히는 메뉴를 찾습니다.

기대값의 출처는 DB 권한표가 아니라 `context-security.xml` 안의 인가 SQL 입니다
(경로 단위 파생 규칙 때문에 권한표만 보면 틀린 기대값이 나옵니다).

> 사전 조건: `RLMS_DB_URL` 환경변수. 내부적으로 `dbq/dbr.ps1` 을 씁니다.

## 4. encpw — 비밀번호 해시 생성

eGov 표준 해시를 만듭니다. **솔트가 로그인 ID** 인 점이 중요합니다.

```bash
java -cp tools/encpw EncPw "<평문 비밀번호>" "<로그인ID>"
```

`.class` 가 동봉되어 있지만, 다시 컴파일하려면:

```bash
javac -encoding UTF-8 tools/encpw/EncPw.java
```

DB 에 직접 넣을 때:

```sql
UPDATE COMTNEMPLYRINFO SET PASSWORD = '<해시>' WHERE EMPLYR_ID = 'sysmen';
```

## 5. dbq/ — Oracle 스크립트 러너

`.sql` 파일을 문장 단위로 파싱해 순서대로 실행합니다. PL/SQL 블록(`/` 로 끝나는
트리거·함수)과 일반 문장을 구분하며, **첫 오류에서 중단**합니다(설치 순서 보장).

```bash
set RLMS_DB_URL=jdbc:oracle:thin:@127.0.0.1:1521:xe
powershell -File tools\dbq\dbr.ps1 <계정> <비밀번호> RLMS\database\newdb\10_tables.sql

# 한 줄 SQL 실행
powershell -File tools\dbq\dbr.ps1 <계정> <비밀번호> exec "SELECT COUNT(*) FROM TB_PROM"
```

- `RLMS_DB_URL` 미지정 시 `jdbc:oracle:thin:@127.0.0.1:1521:xe` 를 씁니다.
- Oracle JDBC(ojdbc11) 는 Java 11+ 클래스파일이라 **JDK 21** 이 필요합니다(`RLMS_JDK`).
- 소스가 바뀌면 `.ps1` 이 알아서 다시 컴파일합니다.

MariaDB / PostgreSQL 용 러너는 `multidb/` 에 있습니다(아래 §7).

## 6. dbdoc/ — 테이블 명세서·ERD 재생성

**스키마를 고쳤으면 문서를 손으로 고치지 말고 다시 뽑으세요.**

```bash
python tools/dbdoc/gen_dbdocs.py
```

- 원천: 각 제품의 `database/newdb/*.sql` (Oracle 정본)의 DDL·`COMMENT ON`
- 출력: `<제품>/docs/테이블_명세서.md`, `<제품>/docs/ERD.md`
- 패키지를 다른 위치로 옮겼으면 `set RLMS_PACKAGE_ROOT=<RESULT 경로>`

ERD 의 관계 정의(어떤 테이블이 무엇과 이어지는지)는 `gen_dbdocs.py` 의 `ERDS` 상수에
들어 있습니다. **테이블을 추가했으면 여기에 관계를 적어야** 다이어그램에 나옵니다.
도메인 분류는 같은 파일의 `DOMAINS` 상수입니다.

## 7. multidb/ — Oracle → MariaDB / PostgreSQL

### 7.1 스크립트 세트 재생성

```bash
set RLMS_WS=C:\eGovFrameDev-4.3.1-64bit\RESULT
python tools/multidb/gen_maria_db.py
python tools/multidb/gen_pg_db.py
```

Oracle 정본(`database/newdb`)을 읽어 `database/maria`, `database/postgres` 를 다시 씁니다.

> `13_triggers_functions.sql`·`00_create_user.sql` 은 생성기 대상이 아닌 수작업
> 이식본입니다 — 덮어쓰이지 않습니다. 스키마를 바꿨다면 직접 확인하세요.

### 7.2 매퍼 변환

```bash
python tools/multidb/map_ora2maria.py     # oracle → maria
python tools/multidb/map_maria2pg.py      # maria  → postgres  (★maria 판이 원본)
```

PostgreSQL 판은 Oracle 이 아니라 **MariaDB 판에서** 만듭니다 — 구조 수작업분을
재사용하기 위해서입니다.

### 7.3 적재 러너

| 도구 | 대상 | 특징 |
|---|---|---|
| `JdbcRun.java` | MariaDB | ⛔ `PIPES_AS_CONCAT,NO_BACKSLASH_ESCAPES` 세션을 **자동 적용**. 직접 `mysql` CLI 로 넣으면 데이터가 조용히 훼손됩니다 |
| `JdbcRunPg.java` | PostgreSQL | plpgsql `$$` 달러 인용을 문장 구분자로 오인하지 않음 |

```bash
javac -encoding UTF-8 -cp <driver.jar> tools/multidb/JdbcRun.java
java -cp <driver.jar>;tools/multidb JdbcRun "jdbc:mariadb://host:3306/rlms" rlms <pw> <파일.sql>
```

### 7.4 SQL 린터

매퍼 XML 의 SQL 을 실제 DB 에 `EXPLAIN` 으로 던져 문법·컬럼 오류를 잡습니다.

| 도구 | 대상 |
|---|---|
| `SqlLint.java` | MariaDB (include 다중 패스 전개) |
| `SqlLintPg.java` | PostgreSQL (autocommit, CDATA 보호, selectKey 제거) |
| `SqlRunPg.java` | PostgreSQL — SELECT 를 **실제로 실행**. EXPLAIN 이 못 잡는 런타임 오류 검출 |

**매퍼를 고쳤으면 린터를 돌리세요.** 3벌 중 하나만 고친 실수를 여기서 잡습니다.

### 7.5 데이터 복사 (기존 DB 에서 이관할 때)

| 도구 | 방향 | 주의 |
|---|---|---|
| `OraToMaria.java` | Oracle → MariaDB | 대상이 0행인 테이블만 복사 |
| `OraToPg.java` | Oracle → PostgreSQL | 채번 동기 내장. **PG 접속은 superuser 필수** |

⚠️ 이관 검증은 **행 수만 비교하면 안 됩니다.** 백슬래시 소실 같은 값 훼손을 못 잡습니다.
문자열 **길이 합계(digest)** 를 양쪽에서 구해 비교하세요.

### 7.6 시드 재생성 (운영 DB 를 정본으로 삼을 때)

이미 운영 중인 DB 의 코드·메뉴·권한을 새 설치 스크립트로 만들고 싶을 때 씁니다.

```bash
set RLMS_DB_URL=jdbc:oracle:thin:@<host>:1521:<sid>
set RLMS_DB_USER=<계정>
set RLMS_DB_PASS=<비밀번호>
python tools/multidb/genseed.py       # 20~26 시드를 다시 씀
python tools/multidb/checkseed.py     # 자기완결성 22항목 검증
```

> 접속정보를 넣지 않으면 실행되지 않습니다(자격증명 하드코딩 방지).

## 10. 언제 무엇을 돌리나 — 체크리스트

| 상황 | 돌릴 것 |
|---|---|
| 화면을 추가했다 | `authcheck.ps1` → **`layoutcheck.ps1`** → `smoke.ps1` |
| 화면 레이아웃(셸)을 고쳤다 | **`layoutcheck.ps1`** |
| 매퍼 SQL 을 고쳤다 | `SqlLint`(maria) / `SqlLintPg`+`SqlRunPg`(pg) → `smoke.ps1` |
| DB 스키마를 바꿨다 | `gen_maria_db.py`·`gen_pg_db.py` → `gen_dbdocs.py` → 적재 → `smoke.ps1` |
| 메뉴명을 바꿨다 | `namecheck.ps1` |
| WAS 를 Tomcat 10/11 로 올렸다 | `smoke.ps1` + **`layoutcheck.ps1`** (`docs/02` §5.3) |
| 배포 직전 | `smoke.ps1` + `authcheck.ps1` + **`layoutcheck.ps1`** |
