# 03. 데이터베이스 가이드

> **앱보다 DB 가 먼저입니다.** DB 가 없으면 애플리케이션이 기동되지 않습니다.

---

## 1. 어떤 DBMS 를 쓸 것인가

세 가지를 모두 지원합니다. **하나만 고르면 됩니다.**

| DBMS | 스크립트 폴더 | 검증 수준 | 비고 |
|---|---|---|---|
| **Oracle** 11g+ | `<제품>/database/newdb/` | ★ 정본 | 전문검색(Oracle Text) 사용 가능 |
| **MariaDB** 10.x | `<제품>/database/maria/` | 라이브 검증 완료 | RLMS 시드는 자동 변환 생성물 |
| **PostgreSQL** 13+ | `<제품>/database/postgres/` | 라이브 검증 완료 | RLMS 시드는 자동 변환 생성물 |
| (Tibero) | — | 미구현 | 설정 자리만 있고 스크립트는 없습니다 |

> `newdb` 라는 폴더 이름은 "신규 DB(=Oracle 클린 설치) 세트" 라는 뜻입니다.
> 다른 두 폴더가 여기서 자동 변환되어 나옵니다. **Oracle 판이 정본**입니다.

선택한 DBMS 는 `globals.properties` 의 `Globals.DbType` 값(`oracle` / `maria` / `postgres`)과
반드시 일치해야 합니다. 매퍼 XML 이 이 값으로 골라집니다
(`*_SQL_oracle.xml` / `*_SQL_maria.xml` / `*_SQL_postgres.xml`).

## 2. 설치 절차 (공통 흐름)

```
① 계정·DB 생성  →  ② 테이블/인덱스/코멘트  →  ③ 트리거·함수
   →  ④ 송무 DDL(해당 제품만)  →  ⑤ 시드 20~26  →  ⑥ FK 제약
```

- **실행 순서를 지켜야 합니다.** 시드는 단순 `INSERT` 라 재실행하면 중복 키 오류가 납니다.
  실패하면 해당 테이블을 truncate 하고 다시 돌리세요.
- **FK(`30_fks.sql`)를 맨 마지막에** 두는 것은 의도된 설계입니다. 시드가 서로 잘 맞물렸는지
  검증하는 역할을 겸합니다. 여기서 오류가 안 나면 참조 정합은 통과입니다.
- 클라이언트 인코딩은 **UTF-8** 이어야 합니다(Oracle 은 `AL32UTF8`).
- Oracle 시드 파일은 첫 줄에 `SET DEFINE OFF` 가 들어 있습니다 — 메뉴명 `Q&A` 의 `&` 가
  치환되지 않도록 하는 장치이므로 **sqlplus / SQL Developer 로 실행**하세요.

### 정확한 파일 순서

**제품·DBMS 마다 15_law_install 의 위치가 다릅니다.** 각 폴더의 `README.md` 가 정본입니다.

| 제품 | 15_law_install 위치 | 이유 |
|---|---|---|
| RLMS | 시드 **앞** | 15 는 DDL 전용, 송무 기준데이터는 `25_seed_domain.sql` 이 넣음 |
| LexPortal | 시드 **뒤** | 15 안에 `NOT EXISTS` 가드 시드가 들어 있음 |
| RegNex | 해당 없음 | 송무 미포함 |

## 3. DBMS별 요점

### 3.1 Oracle (`newdb/`)

1. `00_create_user.sql` — **SYS/SYSTEM** 으로 실행. 계정 생성 + 권한(**CTXAPP 포함**)
   - 파일 안의 비밀번호를 먼저 고치세요.
2. `10` → `11` → `12` → `13` → `14` → `15` → `20`~`26` → `30`
3. `13_triggers_functions.sql` 은 `/` 로 구분된 PL/SQL 블록입니다 — sqlplus 나 SQL Developer 필요
4. `14_oracle_text.sql` 은 한글 lexer + 전문검색 인덱스입니다. CTXAPP 권한이 없으면 실패합니다

### 3.2 MariaDB (`maria/`)

1. 관리자 계정으로 DB·계정 생성 (`maria/README.md` §0)
   ```sql
   CREATE DATABASE rlms CHARACTER SET utf8mb4 COLLATE utf8mb4_general_ci;
   ```
2. 서버는 `lower_case_table_names=1` 전제
3. ⛔ **적재 세션에 반드시 2개 플래그를 켜세요.**
   ```sql
   SET SESSION sql_mode = CONCAT(@@sql_mode, ',PIPES_AS_CONCAT,NO_BACKSLASH_ESCAPES');
   ```
   빠뜨리면 오류 없이 **데이터가 조용히 훼손**됩니다(백슬래시 소실, `||` 오해석).
   동봉 러너 `tools/multidb/JdbcRun` 은 자동으로 겁니다.
4. `COMMENT ON` 이 없어 코멘트가 `CREATE TABLE` 안에 인라인으로 들어 있습니다
   (`12_comments.sql` 없음)

### 3.3 PostgreSQL (`postgres/`)

1. `00_create_user.sql` — 관리자(postgres)로 실행
2. ⛔ **`10_tables.sql` 끝의 `DUAL` 테이블 생성 블록을 지우지 마세요.**
   URL 인가에 쓰이는 공유 SQL 이 `FROM DUAL` 을 씁니다 — 없으면 **로그인 후 전 화면 403**.
3. ⛔ JDBC URL 에 **`?stringtype=unspecified` 필수**
   (eGov VO 가 숫자·날짜도 String 으로 바인딩하기 때문)
4. 트리거·함수 파일(`13`)은 `$$` 달러 인용을 이해하는 러너로 넣으세요
   (`tools/multidb/JdbcRunPg` 또는 `psql`)
5. Oracle Text 는 이식하지 않았습니다 — 통합검색은 부분일치(`STRPOS`)로 동작합니다

## 4. ★ DB 접속정보 암호화 (필수)

`globals.properties` 의 **Url · UserName · Password 세 항목은 모두 암호문**입니다.

> ⛔ **평문을 넣어도 예외가 나지 않습니다.** 복호 루틴이 조용히 깨진 문자열을 돌려주고
> 그걸로 접속을 시도하기 때문에, 원인을 찾기가 매우 어렵습니다. **세 항목을 함께**
> 바꾸세요. `DriverClassName` 은 민감정보가 아니므로 평문 그대로 둡니다.

### 방법 ① 설치 시점 — 명령행 (앱 기동 불필요)

WAR 를 푼 뒤 `WEB-INF` 폴더에서 실행합니다(웹으로는 내려받을 수 없는 위치입니다).

```bash
cd <배포경로>/WEB-INF
encrypt.bat "jdbc:oracle:thin:@127.0.0.1:1521:xe" "계정ID" "비밀번호"    # Windows
sh encrypt.sh "jdbc:oracle:thin:@127.0.0.1:1521:xe" "계정ID" "비밀번호"  # Linux
```

인자를 생략하면 표준입력에서 한 줄씩 읽습니다(비밀번호를 명령 이력에 남기지 않으려면).
도구가 암호화 직후 **복호를 되돌려 검증**하므로 `★복호 왕복 실패` 가 찍히면 키 설정이
잘못된 것입니다.

### 방법 ② 운영 중 — 관리자 화면

**관리자 > 운영관리 > 설정값 암호화** (`/uss/ion/crypto/dbCryptoView.do`, ADMIN 전용).
CLI 와 **완전히 같은 암호문**을 만듭니다.

### 공통 주의

- 암호화는 **DB 종류와 무관**합니다. 키가 하나라서 같은 평문이면 어느 항목이든 암호문이 같습니다.
- **값을 바꾸면 WAS 재기동이 필요합니다** (프로퍼티는 기동 시 1회 로드).
- 자세한 절차: `<제품>/database/INSTALL_CRYPTO.md`

### 🔐 암호화 키도 바꾸는 것을 권장합니다

암호화 키는 `src/main/resources/egovframework/spring/com/context-crypto.xml` 의
`algorithmKey` 입니다. 개발사 기본값이 그대로 들어 있으니 운영 전환 시
**고객 전용 값으로 교체**하세요.

`algorithmKeyHash` 는 그 키의 검증값이라 **함께 갱신**해야 합니다.
계산식은 `Base64(SHA-256(키))` 입니다.

```bash
python -c "import hashlib,base64,sys;print(base64.b64encode(hashlib.sha256(sys.argv[1].encode()).digest()).decode())" "<새 키>"
```

순서를 지키세요 — **키·해시 교체 → 접속정보 재암호화 → WAS 재기동**.
(키를 바꾸면 기존 암호문은 전부 무효가 됩니다. 불일치 시 CLI 가 `★복호 왕복 실패` 로 알려줍니다.)

> 송무 모듈의 주민등록번호 암호화 키(`Globals.law.cryptoKey` / `…KeyHash`)도
> **같은 계산식**입니다. 함께 교체하세요.

## 5. 스키마의 성격 — 알고 있어야 할 것

| 사실 | 의미 |
|---|---|
| **FK 제약이 26건뿐** | 레거시에서 이관된 `TB_*` 테이블에는 FK 가 없습니다. **DB 가 참조무결성을 지켜주지 않습니다** — 삭제·이동은 서비스 계층에서 연쇄 처리해야 합니다 |
| **`TB_*` 는 PK 제약도 없음** | 논리 키는 애플리케이션이 보장합니다. 각 테이블 첫 컬럼이 논리 키입니다 |
| **채번은 `COMTECOPSEQ`** | 시퀀스를 쓰지 않습니다. 채번 행이 없으면 **해당 기능의 첫 저장이 실패**합니다 (`26_seed_idgn.sql`) |
| **논리 삭제** | `SDEL_YN='N'` / `SDISP_YN='N'` 은 tombstone 입니다. 물리 삭제하지 않습니다 |
| **날짜가 문자열** | 대부분 `VARCHAR2`. `SINS_DT`=`YYYYMMDDHH24MISS`, `S*_DT`=`YYYYMMDD` |
| **`SSYS_ID`** | 단일 시스템 고정값. **조회 조건으로 쓰지 않습니다** |
| **트리거 7종** | 규정 삭제 cascade 체인입니다. 앱이 명시적으로 의존하므로 지우면 안 됩니다 |

전 테이블·전 컬럼 명세는 **`<제품>/docs/테이블_명세서.md`**,
핵심 관계도는 **`<제품>/docs/ERD.md`** 를 보세요.

## 6. 시드로 들어가는 것 / 안 들어가는 것

### 들어갑니다

- 공통코드, 프로그램·메뉴·메뉴별 권한, 권한·롤·롤계층
- 예시 부서 7종, **예시 계정 4종**, 로그인 정책
- 공지사항 게시판 1개 + 템플릿, 개정구분, 브랜드
- (송무 포함 제품) 법원 22건 + 소송비용 요율 41건

### 안 들어갑니다 (의도)

- 규정·조문 등 **운영 데이터** — 클린 시작입니다
- 분류(`TB_CATE`) — 구분(법령/사규) 2종만 넣고, 하위 분류는 화면에서 직접 만듭니다
- 데모 게시판(갤러리·자료실 등) — 공지사항 1개만 넣습니다

### 예시 계정 — ⚠️ 운영 전 반드시 변경

| 계정 | 초기 비밀번호 | 권한 |
|---|---|---|
| `sysmen` | `asdqwe123!` | ROLE_ADMIN |
| `approver` | `rlms1234!` | ROLE_APPROVER |
| `lawmgr` | `rlms1234!` | ROLE_LAW_MGR |
| `user` | `rlms1234!` | ROLE_USER |

변경 방법 2가지:

1. **화면에서** — 로그인 후 내 계정 > 비밀번호 변경 (권장)
2. **해시를 직접 만들어 UPDATE** — 솔트가 **로그인 ID** 입니다
   ```bash
   java -cp tools/encpw EncPw "<새 비밀번호>" "<로그인ID>"
   ```

## 7. 채번(`COMTECOPSEQ`) 주의

- 시퀀스 대신 이 테이블 + `EgovIdGnrService` 로 채번합니다.
- **기존 데이터가 있는 DB 에 적용**할 때는 `NEXT_ID` 가 현재 `MAX(PK)` 보다 커야 합니다.
  낮으면 첫 저장에서 PK 충돌이 납니다.
- 시드가 미리 값을 올려 두는 키가 2개 있습니다 —
  `LAW_COURT_ID`=200(법원 시드 최대 194), `LAW_CALC_RATE_ID`=100(요율 41행).

RLMS 는 통합본이라 송무가 기본 포함입니다. 쓰지 않을 경우 **메뉴만 내리면** 됩니다

## 9. 문제 해결

| 증상 | 원인 | 조치 |
|---|---|---|
| 기동은 되는데 DB 접속만 실패 | 세 항목 중 일부가 평문 | 세 항목 모두 재암호화 → **재기동** |
| `★복호 왕복 실패` | `context-crypto.xml` 키 불일치 | `algorithmKey` / `algorithmKeyHash` 확인 |
| 값을 바꿨는데 반영 안 됨 | 기동 시 1회 로드 | WAS 재기동 |
| 시드 실행 중 중복 키 오류 | 시드 재실행 | 해당 테이블 truncate 후 다시 |
| `30_fks.sql` 에서 오류 | 시드 누락/순서 오류 | 오류 메시지의 참조 테이블 시드부터 재확인 |
| 저장 시 "시스템 에러" | 채번 행 없음 | `26_seed_idgn.sql` 실행 확인 |
| (PG) 로그인 후 전 화면 403 | `DUAL` 테이블 없음 | `10_tables.sql` 의 DUAL 블록 재실행 |
| (Maria) 데이터에 백슬래시 사라짐 | 세션 플래그 누락 | truncate 후 플래그 켜고 재적재 |
| (Oracle) 전문검색 인덱스 실패 | CTXAPP 권한 없음 | `00_create_user.sql` 의 GRANT 확인 |

## 10. 스키마를 바꿀 때

1. **Oracle 정본(`newdb/`)을 먼저 고칩니다.**
2. MariaDB·PostgreSQL 판을 다시 뽑습니다.
   ```bash
   set RLMS_WS=<제품들이 들어있는 폴더>
   python tools/multidb/gen_maria_db.py
   python tools/multidb/gen_pg_db.py
   ```
3. 문서를 다시 뽑습니다.
   ```bash
   python tools/dbdoc/gen_dbdocs.py
   ```
4. 매퍼도 3벌(oracle/maria/postgres)을 **함께** 고칩니다 — 한 벌만 고치면
   다른 DBMS 에서 조용히 깨집니다.

> `13_triggers_functions.sql`·`00_create_user.sql` 은 생성기 대상이 아닌 수작업
> 이식본입니다. 스키마를 바꿨다면 이 두 파일은 직접 확인하세요.
