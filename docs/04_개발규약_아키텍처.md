# 04. 개발 규약 · 아키텍처

> 코드를 고치기 전에 반드시 읽어야 하는 문서입니다.
> §10 의 **⛔함정 모음**은 실제로 사고가 났던 항목만 모은 것입니다.

---

## 1. 레이어 구조

전자정부 표준프레임워크의 표준 Layered Architecture 를 그대로 씁니다.

```
Controller (web)        @Controller, URL 매핑, 화면 반환
    ↓
Service (service)       인터페이스 — 트랜잭션 경계
    ↓
ServiceImpl (impl)      @Service, 비즈니스 로직, @Transactional
    ↓
Mapper (mapper)         @Mapper 인터페이스
    ↓
Mapper XML              실제 SQL — DBMS별 3벌
```

한 기능(예: 규정) 폴더 구조:

```
narainet/rlms/prom/
├─ web/          PromController.java
├─ service/      PromService.java, PromVO.java
│   └─ impl/     PromServiceImpl.java
└─ mapper/       PromMapper.java

egovframework/mapper/rlms/prom/
├─ Prom_SQL_oracle.xml
├─ Prom_SQL_maria.xml
└─ Prom_SQL_postgres.xml
```

## 3. 자바 코딩 규약

### 3.1 JDK 1.8 고정

```java
// ⛔ 쓸 수 없습니다 (Java 9+)
var list = new ArrayList<String>();
record Point(int x, int y) {}
String s = """text block""";

// ✅
List<String> list = new ArrayList<>();
```

### 3.2 Lombok 적극 사용

`@Getter`, `@Setter`, `@Builder`, `@RequiredArgsConstructor` 로 보일러플레이트를 없앱니다.

### 3.3 컬렉션 · 트랜잭션

- `Hashtable`·`Vector` 금지 → `HashMap<String,Object>`, `ArrayList<T>` (제네릭 필수)
- 트랜잭션은 `@Transactional`. 수동 커밋/롤백 로직을 만들지 않습니다.

### 3.4 SQL 은 자바에 두지 않습니다

`StringBuffer` 로 SQL 을 조립하지 말고 **전부 MyBatis XML** 로 뺍니다.

## 4. MyBatis 규약

### 4.1 DBMS 3벌을 항상 함께 고칩니다

```
Prom_SQL_oracle.xml
Prom_SQL_maria.xml      ← 하나만 고치면 다른 DBMS 에서 조용히 깨집니다
Prom_SQL_postgres.xml
```

- namespace 는 FQN(매퍼 인터페이스 전체 이름)으로 씁니다.
- `NVL`·`TO_CHAR(날짜)` 는 MariaDB 네이티브라 **변환하지 않습니다**.
- PostgreSQL 판은 `FROM DUAL` 을 제거하고 `ROWNUM` → `ROW_NUMBER() OVER ()` 로 바꿉니다.

### 4.2 CDATA 스타일

부등호가 들어가면 CDATA 로 감쌉니다.

```xml
<![CDATA[
  AND SSTART_DT <= #{today}
]]>
```

### 4.3 ⛔ OGNL 문자열 리터럴은 큰따옴표

```xml
<if test='useAt == "Y"'>      <!-- ✅ 큰따옴표 -->
<if test="useAt == 'Y'">      <!-- ⛔ 'Y' 를 char 로 봐서 오작동 -->
```

### 4.4 ⛔ XML 주석 안에 `--` 금지

XML 주석(`<!-- -->`) 안에 `--` 가 또 나오면 파서가 깨집니다.
SQL 주석을 그대로 감싸다가 자주 사고가 납니다.

## 5. 채번 (PK 생성)

**시퀀스를 쓰지 않습니다.** `COMTECOPSEQ` 테이블 + `EgovIdGnrService` 로 채번합니다.

```java
@Resource(name = "egovPromIdGnrService")
private EgovIdGnrService idgnrService;

int promNo = Integer.parseInt(idgnrService.getNextStringId());
```

- 채번 서비스 빈은 `resources/egovframework/spring/com/idgn/context-idgn-*.xml` 에 정의합니다.
- **새 테이블을 만들면 채번 행과 빈을 함께 추가**해야 합니다. 없으면 그 기능의
  **첫 저장이 실패**합니다.
- ⛔ `SQ_*.NEXTVAL` 같은 시퀀스 사용 금지.

## 6. ★ URL 접근제어 — 코드가 아니라 DB 가 원천

이 시스템에서 **가장 자주 실수하는 지점**입니다.

새 화면(`/rlms/foo/bar.do`)을 만들면 코드만으로는 **접근이 열리지 않습니다.**
아래 3곳에 DB 등록이 필요합니다.

| 순서 | 테이블 | 넣는 것 |
|---|---|---|
| 1 | `COMTNPROGRMLIST` | 프로그램(=URL) 1행 |
| 2 | `COMTNMENUINFO` | 메뉴 1행 (프로그램을 참조) |
| 3 | `COMTNMENUCREATDTLS` | 메뉴 × 권한(ROLE) 매핑 |

- 인가 규칙은 위 3표를 조인한 **인라인 SQL** 로 만들어지며, 그 SQL 은
  `context-security.xml` 안에 있습니다.
- 폴더 단위 패턴 매칭이 있어 기존 폴더 아래 URL 은 자동으로 커버되는 경우가 있지만,
  **새 폴더**를 만들면 반드시 등록해야 합니다.
- 등록 후에는 **재기동**해야 반영됩니다.

> 403 이 나면 십중팔구 이 등록 누락입니다.
> 점검 도구: `tools/authcheck.ps1` (`06_도구_사용설명서.md` §3)

## 8. 화면(View) 규약

### 8.1 레이아웃 셸 (JSP 태그파일)

화면 JSP 는 **자기 자신을 `<lay:layout>` 으로 감쌉니다.** 응답을 가로채는 필터는 없습니다.
(2026-08-07 SiteMesh 2 제거 — 경위는 `docs/08` §1)

| 셸 (`WEB-INF/tags/shell/`) | 용도 |
|---|---|
| `front.tag` | 사용자 화면 |
| `mgr.tag` | 관리자 화면 |
| `popup.tag` | 팝업 / iframe / dialog |
| `plain.tag` | 장식 없음(로그인·에러 등) |

**어느 셸을 쓸지는 URL 이 정합니다** — `WEB-INF/layouts.xml` 의 패턴 매핑을
`EgovLayoutResolver` 가 해석합니다(정확일치 > 최장 와일드카드 > 기본값).
같은 JSP 가 URL 에 따라 다른 셸로 떠야 하기 때문입니다
(예: 게시판 상세는 `/cop/bbs/user/*` → 사용자 셸, `/cop/bbs/*` → 관리자 셸).

```jsp
<%@ taglib prefix="lay" tagdir="/WEB-INF/tags" %>
<c:set var="pageTitle">규정 목록</c:set>
<c:set var="pageHead">
  <link rel="stylesheet" href="..."/>     <%-- 이 페이지 전용 head 자원 --%>
</c:set>
<lay:layout title="${pageTitle}" head="${pageHead}">
  ...본문...
</lay:layout>
```

**⛔ 태그 본문은 `scriptless`** — `<lay:layout>` 안에서는 `<% %>` / `<%= %>` 를 못 씁니다.
필요하면 **여는 태그 앞**에서 값을 만들어 두고 본문에서는 EL 로 참조하십시오.

```jsp
<c:set var="fileMaxSize"><%= EgovProperties.getProperty("Globals.fileUpload.maxSize") %></c:set>
<lay:layout ...>
  ... parseInt('${fileMaxSize}', 10) ...
</lay:layout>
```

**⛔ 셸을 씌우면 안 되는 화면**이 있습니다 — 자체 완결 레이아웃(`code404/500.jsp`,
LexPortal 포탈 공개 메인)과 다른 화면이 `c:import` 로 끌어 쓰는 조각입니다.
전자는 `<lay:layout>` 을 아예 쓰지 않고, 후자는 `layout.tag` 가 include 요청을 감지해
셸을 건너뜁니다.

화면을 추가한 뒤에는 **`tools/layoutcheck.ps1`** 로 확인하십시오 —
래핑 누락(맨몸)과 이중 래핑(`<html>` 2개)을 잡아 줍니다.

### 8.2 KRDS 디자인 시스템 우선

정부 디자인 시스템(KRDS) 클래스를 기본으로 씁니다. 전자정부 표준 공통컴포넌트의
기본 스타일보다 **KRDS 를 우선**합니다.

- 폼: `krds-form` + `tbl-detail` 패턴이 정본입니다.
- 입력 컴포넌트 크기는 전역 `small` 이 기본입니다.
- CSS/JS 를 고치면 **캐시 버스터를 올려야** 반영됩니다.

### 8.3 ⛔ JSP 함정

```jsp
<%-- ⛔ JS 주석 안에 커스텀 태그를 두면 파싱되어 500 이 납니다 --%>
// <c:if test="...">   ← 주석이라도 태그는 실행됩니다

<%-- ⛔ <c:choose> 의 직접 자식으로 HTML 주석을 두면 안 됩니다 --%>
<c:choose>
  <!-- 설명 -->        ← 오류
  <c:when …>
```

- `.jspf` 파일에는 `pageEncoding` 을 반드시 넣습니다.
- `jsp:include` 는 별도 `pageContext` 라 변수가 전달되지 않습니다 —
  `<c:set scope="request">` 를 쓰세요.
- 동적으로 주입하는 UI 에 스타일 없는 맨몸 컨트롤(`<input>` 단독)을 두지 않습니다.

### 8.4 리다이렉트 뒤 한글 메시지

`redirect:` 앞에서 모델에 담은 값은 사라집니다. **flash attribute** 를 쓰세요.

## 11. 개발 워크플로 권장

1. **한 곳에서만 작업합니다.** 같은 파일을 여러 사본에서 고치면 반영 위치를 잃습니다.
2. 빌드: `mvn -o compile` (⛔ `clean` 금지 — WTP 배포본이 날아갑니다)
3. 클래스 변경은 WTP 가 자동 리로드하지만, **6~8회 반복되면 선제적으로 재기동**하세요.
4. 화면을 만들었으면 **URL 등록 → 재기동 → 스모크**까지가 한 세트입니다.
5. DB 스키마를 바꿨으면 **매퍼 3벌 + 문서 재생성**까지가 한 세트입니다.
