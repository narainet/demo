## A. 규정관리 (RegNex · RLMS)

### A-1. 분류 체계 — 구분 → 분류 트리

```
구분(SGUBUN)         공통코드 그룹 'SGUBUN' 의 상세코드    예) 법령 / 사규
 └ 분류(TB_CATE)     자기참조 트리 (IREF)                  예) 인사 > 복무 > 근태
    └ 규정(TB_PROM)  회차 단위 행
```

- 구분은 **공통코드**입니다(`/sym/ccm/cca` 가 아니라 분류관리 화면에서 다룹니다 —
  `Globals.CodeManage.ProtectedCodeIds=SGUBUN` 으로 공통코드 화면에서는 숨깁니다).
- `TB_CATE` 는 자기참조 트리이면서 **조상 경로를 비정규화**해 둡니다
  (`IREF_LV_1`~`IREF_LV_10`). 트리를 옮기면 이 값들도 갱신해야 합니다.
- `SFULL_NAME` 은 전체 경로 문자열 캐시입니다.

**열람 제한**은 두 층이 직교합니다.

| 층 | 테이블 | 의미 |
|---|---|---|
| 구분 단위 | `TB_GUBUN_READER` | 지정 시 그 부서/개인만. **미지정이면 전체 공개** |
| 분류 단위 | `TB_CATE_READER` | 분류별 열람 허용 대상 |
| 분류 소유 | `TB_CATE_OWNER` | 그 분류를 편집할 수 있는 대상 |

> 공개 열람 모드(`Globals.rlms.publicFront=Y`)에서도 이 제한은 **익명 사용자에게 그대로
> 적용**됩니다. 제한이 걸린 분류는 비로그인에게 차단됩니다.

### A-2. 규정 회차와 현행 판정

- 회차 = `TB_PROM` 1행. 같은 규정의 회차들은 `ILAW_ID` 가 같고 `ILAW_NO` 로 순번이 붙습니다.
- **현행 판정**: `SSTART_DT`(시행일) ≤ 오늘 이면서 `SNULL_DT`(폐지일)가 지나지 않은 회차.
  결과는 `SEXISTING_YN='Y'` 로 캐시되며 **같은 `ILAW_ID` 안에서 1건만 Y** 입니다.
- 시행예정 회차는 목록에 뱃지로 노출됩니다.
- **폐지일 변경은 승인 게이트를 지납니다** — 현행 회차의 `SNULL_DT` 는 승인 후에만 반영됩니다.

### A-3. 조문 본문 — 두 가지 형식

`TB_PROM.SPROV_FG` 가 형식을 정합니다.

#### VERSION(구조형) — `TB_PROV_VRSN`

평문 textarea 에 입력한 본문을 파서가 **조/항/호 단위 행**으로 분해합니다.

| 컬럼 | 뜻 |
|---|---|
| `SFULL_ITEM` | 전체 조항 식별자 (회차 간 비교의 키) |
| `SITEM` | 조 번호 — **계보 키**이며 정렬키가 아닙니다 |
| `IINDEX` | 실제 정렬 순서 |
| `SUNIT_TYPE` | 조/항/호 구분 |
| `SGAEJUNG_TYPE` | 이 회차에서 신설/변경/삭제 중 무엇인지 |
| `SDISP_YN` | `N` = 삭제 표식(tombstone) |

- **본문 입력은 평문 textarea 가 정본**입니다. 에디터로 바꾸면 파서가 깨집니다.
- 조문 번호를 다시 매길 때 `SITEM` 을 정렬키로 오해하면 계보가 끊깁니다.

#### HTML(자유형) — `TB_PROV_HTML`

조 단위로 HTML 본문 1행. 표가 많은 규정용입니다. 저장 시 검색용으로
`TB_PROV_VRSN` 에도 분해해 넣습니다.

> 편집기가 본문을 **raw 로 렌더링**하는 것은 의도된 설계입니다(HTML 규정 지원).
> XSS 로 오인해 이스케이프를 넣으면 화면이 깨집니다.

### A-4. 개정 처리 — 누적 모델

새 회차를 만들 때 직전 회차의 조문을 **복사**해 옵니다. 그 뒤

- 바뀐 조문 · 새로 생긴 조문 · 삭제 표식(tombstone)만 **새 회차가 소유**합니다.
- 따라서 어떤 회차를 조회해도 그 시점의 전문을 온전히 재구성할 수 있습니다.

연혁을 삭제하면 그 회차가 소유한 조문·별표·관련자료가 **연쇄 삭제**됩니다
(DB 트리거 7종이 이 체인을 담당합니다 — 지우면 안 됩니다).

### A-5. 승인 워크플로 (`TB_PROM_WRK`)

```
편집중  →  승인요청  →  승인완료 / 반려
                 │
                 └ 심사 중에는 해당 회차 편집이 잠깁니다
```

- 상태 이력이 행으로 쌓입니다(`SSTATUS`, `SUSER_ID`, `SINS_DT`, `SREASON`).
- 승인자(`ROLE_APPROVER`)만 승인/반려할 수 있습니다.
- **미승인(draft) 회차는 사용자 화면에 노출되지 않습니다.**

### A-6. 관련자료 — 8액션 허브·상세 구조

자료 1건 = `TB_REL_VRSN` 허브 1행. `STABLE` 값이 실제 상세 테이블을 가리킵니다.

| STABLE | 상세 테이블 | 내용 |
|---|---|---|
| `FILE` | `TB_REL_FILE` | 일반 파일 |
| `WORD` | `TB_REL_WORD` | 워드·HWP (HTML 변환본 보관) |
| `IMG` | `TB_REL_IMG` | 이미지 |
| `ORGN` | `TB_REL_ORGN` | 원본(정본) 파일 |
| `HTML` | `TB_REL_HTML` | 직접 작성한 표·본문 |
| `LNK` | `TB_REL_LNK` | 외부 URL |
| `DMN_LNK` | `TB_REL_DMN_LNK` | 다른 규정·조문 연계 |

- 파일 실체는 `TB_ATTACH` 가 보관합니다(도메인 첨부는 `TB_ATTACH`, 게시판 등 표준
  모듈은 `COMTNFILE`/`COMTNFILEDETAIL`).
- 카테고리(`TB_REL_VRSN_CATE`)는 본문/붙임/양식 같은 그룹 헤더이며, 새 회차를 만들면
  기본 3종이 자동 생성됩니다.
- 원본 다운로드 허용 여부는 카테고리의 `SORGNDOWN_YN` 정책으로 통제합니다.

### A-7. 조문 자동 링크와 제외 범위

본문 안의 "○○규정 제5조" 같은 문자열을 자동으로 링크로 바꿉니다.
링크를 걸면 안 되는 범위는 `TB_REL_EXCL_LNK` 로 지정합니다(구분/분류/특정 규정 3종).

> `TB_REL_EXCL_LNK`(자동링크 제외)와 `TB_REL_DMN_LNK`(수동 규정 연계)는
> **서로 직교**합니다. 하나를 고칠 때 다른 하나를 건드리지 마세요.

### A-8. 필수 열람 (의무 숙지)

승인된 회차에 열람 의무를 지정합니다.

```
지정(TB_READ_DUTY)  ─ 회차당 1건, 기한(SDUE_DT)
   ├ 대상(TB_READ_DUTY_TGT)  전사(SALL_YN=Y) / 부서(DEPT) / 개인(USER)
   └ 확인(TB_READ_DUTY_CHK)  ① 열람 자동기록 SREAD_DT
                              ② 숙지 확인 버튼 SCONF_DT
```

- 2단계로 나눈 이유는 "봤다"와 "숙지했다"를 구분해 증빙을 남기기 위해서입니다.
- 사용자 홈에 미확인 카드가 뜨고, 관리자는 열람률 현황을 봅니다.
- 증빙은 영구 보존 대상입니다 — 삭제 로직을 넣지 마세요.

### A-9. 통합검색 (4축)

한 번의 검색어로 네 가지를 동시에 찾습니다.

| 축 | 원천 |
|---|---|
| 규정 | `TB_PROM.SSEARCH_TEXT` |
| 조문 | `TB_PROV_VRSN.SSEARCH_TEXT` (Oracle 은 Oracle Text 인덱스) |
| 관련자료 | `TB_REL_WORD.SSEARCH_TEXT` 등 |
| 게시판 | `COMTNBBS` |

- Oracle 에서는 `TB_PROV_VRSN.SCONTENTS` 에 CONTEXT 인덱스 + 한글 lexer 를 씁니다.
- MariaDB·PostgreSQL 에서는 부분일치(`LIKE` / `STRPOS`)로 동작합니다.
- 검색어는 `TB_STATS_KWD` 에 적재되어 인기 검색어 통계가 됩니다.

### A-10. 그 밖의 규정 기능

| 기능 | 요점 |
|---|---|
| 별표/서식 (`TB_DOCU`) | 회차 단위 누적 모델. 조문과 같은 방식 |
| 규정맵 (`TB_PROM_MAP`) | 업무 기능별 재배치 트리. 폴더(`SPROM_YN=N`) + 규정 leaf(`Y`) |
| 즐겨찾기 (`TB_FAVOR`) | `ILAW_ID`+`SITEM` 로 조항 지정. 개정 소식 알림(`ISEEN_LAW_NO`) |
| 메모 (`TB_MEMO`) | 개인 메모. 사용자별 격리 |
| 만족도 (`TB_PROM_STSFDG`) | 회차당 1인 1회 |
| 법령질의 (`TB_LAWQUEST`) | 외부 로펌 자문 의뢰·회신. 답변 권한자만 회신 작성 |
| 전문 뷰어 | PDF·PPTX 내보내기. 한글 폰트 경로 `Globals.rlms.PdfFontPath` |

## B. 송무 (LexPortal · RLMS)

### B-1. 사건 구조

`LAW_SUIT` 1행 = **1심급**. 상급심은 별도 행이고 `FIRST_SUIT_ID` 로 묶입니다.

- 최초심은 `FIRST_SUIT_ID` = 자기 `SUIT_ID`
- 상급심은 원심의 값을 그대로 승계

사건 1건에 붙는 것들:

| 테이블 | 내용 |
|---|---|
| `LAW_SUIT_PARTY` | 원고/피고/보조참가인. **주민등록번호는 ARIA 암호화** |
| `LAW_SUIT_STAFF` | 소송수행자 (부서는 표준 `COMTNORGNZTINFO` 연동) |
| `LAW_SUIT_LAND` | 사건 토지 — 지번 목록. 지도 표시의 원천 |
| `LAW_SUIT_PROG` | **진행상황과 기일이 같은 테이블**입니다. 소송등록 그리드와 일정관리 달력이 같은 원천 |
| `LAW_SUIT_RSLT_HIST` | 결과 변경 이력 (결과 필드만 이력화) |
| `LAW_SUIT_DOC` | 소송문서. 등록하면 승인대기, 수정하면 대기로 리셋 |
| `LAW_SUIT_COST` | 소송비용 |
| `LAW_SUIT_LAWYER` | 선임 (사건 × 변호사). 만족도 평가의 단위 |

### B-2. 소송의뢰 흐름

```
현업 사용자          법무팀
  신청(front)  →  검토  →  승인 ─→ 사건(LAW_SUIT) 생성·연계
                        └ 반려 (사유 기록)
```

- 의뢰(`LAW_SUIT_REQ`)에는 사건경과(`…_HIST`)와 수행 보조자(`…_HELPER`)가 붙습니다.
- 승인되면 `LAW_SUIT_REQ.SUIT_ID` 로 사건과 연결됩니다.

### B-3. 소송비용 계산기

- 요율표 `LAW_CALC_RATE` 는 **타입 × 항목 × 적용시작일** 세트입니다.
- 기준일로 조회하면 `APPLY_DT` 가 그 이하인 **최신 세트**를 씁니다.
  → 법이 개정되면 새 `APPLY_DT` 세트를 추가만 하면 되고, 과거 계산은 그대로 재현됩니다.
- **계산 공식(뼈대)은 화면 JS 에 있고, 숫자만 DB 에 있습니다.**
  요율만 바뀌면 화면에서 관리하고, 공식이 바뀌면 JS 를 고쳐야 합니다.

### B-4. 주민등록번호 암호화

| 항목 | 내용 |
|---|---|
| 저장 | `LAW_SUIT_PARTY.JUMIN_ENC` — ARIA 암호문 |
| 키 | `Globals.law.cryptoKey` (**고객사 전용 값으로 교체 필수**) |
| 키 검증 | `Globals.law.cryptoKeyHash` = `Base64(SHA-256(키))` |
| 화면 | 마스킹만 표시 |

키를 바꾸면 **기존 암호문을 복호할 수 없습니다.** 운영 데이터가 쌓이기 전(=인수 직후)에
교체하세요.

### B-5. 지도 표시

`Globals.law.kakaoMapAppKey` 가 설정되어 있으면 사건 토지를 지도에 찍고,
**비어 있으면 지번 목록으로 자동 대체**됩니다. 키가 없어도 기능은 동작합니다.

### B-6. 첨부 정책 (규정 모듈과 다릅니다)

송무는 **전자정부 표준 첨부**(`COMTNFILE` / `COMTNFILEDETAIL`, `ATCH_FILE_ID`)를 씁니다.
규정 모듈의 `TB_ATTACH` 와 다릅니다 — 의도된 차이입니다.

업로드 물리 경로는 기능별로 나뉩니다.

```
Globals.fileStorePath.Law = D:/upload/law/
   └ req / doc / assign / seize / receipt   ← 기능별 하위 폴더
```

## C. 공통 기반

### C-1. 게시판

- 게시판을 만들면 **메뉴가 자동으로 연결**됩니다
  (`Globals.Bbs.UserMenuFolderNo` 아래에 자식 메뉴가 생성, 최대 99개).
- 작성 권한은 `COMTNBBSWRITEAUTHOR` 로 롤 단위 지정합니다.
- 본문 에디터는 CKEditor 이고, 이미지 첨부는 별도 경로로 저장됩니다.
- 만족도(`COMTNSTSFDG`)를 게시글 단위로 받을 수 있습니다.

### C-2. 파일 첨부 2계층

```
COMTNFILE        묶음 1행  (ATCH_FILE_ID)
   └ COMTNFILEDETAIL  개별 파일 N행
```

- 게시글·FAQ 등은 `ATCH_FILE_ID` 로 묶음을 참조합니다.
- ZIP 일괄 다운로드는 `/cmm/fms/FileZipDown.do` 공용 컴포넌트입니다.
- ⚠️ `FileDown.do` 는 브라우저 User-Agent 가 없으면 무조건 오류 화면을 돌려줍니다
  (스크립트로 테스트할 때 UA 를 넣어야 합니다).

### C-3. 로그인·계정 정책

| 정책 | 설정 |
|---|---|
| 인증 방식 | `Globals.Auth = security` |
| 로그인 실패 잠금 | `Globals.login.Lock`, `Globals.login.LockCount` (기본 5회) |
| 비밀번호 유효기간 | `Globals.ExpirePwdDay` (기본 180일) |
| 휴면 계정 | `Globals.DormantDay` (기본 365일, `0`=비활성) |
| 중복 로그인 | 제어됨 (나중 로그인이 이전 세션을 끊음) |

### C-4. 브랜드 설정

`COM_BRAND` 테이블 + 관리자 화면(운영관리 > 브랜드 설정)에서 시스템 이름·로고·파비콘을
바꿉니다. 로고·파비콘 업로드 경로는 `Globals.fileStorePath.Brand` 입니다.

### C-5. 로그·통계

| 로그 | 테이블 | 적재 시점 |
|---|---|---|
| 로그인 | `COMTNLOGINLOG` | 로그인/로그아웃 |
| 웹 접속 | `COMTNWEBLOG` | 페이지 요청 |
| 시스템 | `COMTNSYSLOG` | 서비스 호출 |
| 활동 | `TB_ACT_LOG` | 열람·다운로드 등 사용자 행위 |
| 규정 조회 | `TB_STATS_FT_VIEW` | 규정 전문 열람 |
| 게시글 조회 | `TB_STATS_BBS_VIEW` | 게시글 열람 |
| 검색어 | `TB_STATS_KWD` | 검색 1회당 1행 |

신규 설치 직후에는 당연히 비어 있고, 사용하면서 쌓입니다.

## D. 화면 반응형 · 접근성

- 전 화면이 모바일(375px)까지 대응되어 있습니다.
